# Правила работы с проектом «Герои класса»

Обязательны для людей и ИИ-агентов. Ограничения продукта — в [PRODUCT.md](PRODUCT.md), планы — в [ROADMAP.md](ROADMAP.md), причины решений — в [DECISIONS.md](DECISIONS.md).

## Архитектура

Проект остаётся модульным монолитом: `apps/api`, `apps/web`, `packages/shared`, `services/detector`, `e2e`. Новые сервисы и npm-пакеты ради разделения кода не заводим: внутри одного продукта их цена выше пользы. Отдельный сервис оправдан только другой средой выполнения или требованиями изоляции, как у `services/detector`.

Перенос на эту схему завершён: новый код сразу пишется по ней, а новый домен получает свой модуль и свою фичу.

### API: `apps/api/src`

```
modules/<домен>/
  index.ts       публичный интерфейс модуля
  routes.ts      HTTP: разбор запроса, права, вызов сервиса (при нескольких ролях: teacher.routes.ts, student.routes.ts)
  service.ts     бизнес-правила и работа с базой (несколько тем: stats.service.ts, weekly-stats.service.ts)
  schemas.ts     схемы zod, если их больше двух
platform/        db, auth, env, errors, dates, credentials, storage: без знания о доменах
routes/          сборки ролей: teacher.ts, student.ts, parent.ts
app.ts           сборка приложения
```

Домены: `access`, `accounts`, `codes`, `groups`, `students`, `parents`, `reasons`, `points`, `attendance`, `rewards`, `teams`, `goals`, `plan`, `calendar`, `home`, `files`, `feed`, `messages`, `notifications`, `hero`, `badges`, `portfolio`, `profile`, `reports`.

- `routes/*.ts` только собирают кабинет роли: роль проверяется один раз, модули подключаются через `.route()`. Запросов и правил там нет.
- `routes` не обращается к Prisma напрямую: запросы и правила живут в `service`.
- Из другого модуля импортируй только его `index.ts`, а не внутренние файлы.
- Зависимости модулей идут в одну сторону, циклов нет. Сводные модули (`notifications`, `reports`, `badges`, `profile`) читают другие, а те о них не знают. Если нужна обратная связь, вынеси общее в третий модуль.
- `platform/` не импортирует модули.
- Доступ к группе и ученику проверяется только через `teacherGroup`, `teacherStudent` и `groupsOf` из модуля `access`, родителя — через `parentChild`. Своих условий принадлежности не пишем. `access` нужен почти всем доменам, поэтому не входит в `groups` и сам не зависит от других модулей.
- Операции, зависящие от проверки и записи, выполняются в транзакции: блокировка группы (`lockGroup` из `access`) для баллов, целей и плана урока, блокировка ученика (`lockStudent` из `access`) для наград и домашних баллов.

### Веб: `apps/web/src`

```
app/             запуск, маршруты, провайдеры, раскладка
pages/           тонкие страницы маршрутов: собирают фичи, логики не содержат
features/<домен>/
  index.ts       публичный интерфейс фичи
  api.ts         запросы домена
  components/    компоненты домена
  hooks/         хуки домена
ui/              общие элементы без знания о домене: Modal, Toast, ProgressBar
lib/             общие утилиты без React-компонентов домена
```

- Зависимости идут только вниз: `app → pages → features → ui, lib`. `ui` и `lib` не импортируют `features` и `pages`.
- Страница не импортирует другую страницу, компонент не импортирует страницу. Общая часть переносится в `features` или `ui`.
- Фича импортирует другую фичу только через её `index.ts`.
- `early.ts` и `routes.ts` встраиваются в HTML и остаются без зависимостей.
- Переносишь файл — обнови `PAGE_MODULES` в `app/routes.ts` и список ядра `APP_CHUNK` в `vite.config.ts`: там пути записаны строками, и ошибка не видна компилятору. Проверь вес ядра после сборки.
- Первый экран держим лёгким: тяжёлые библиотеки (Motion и подобные) подключаются лениво и не попадают в ядро.
- Ядро берёт из фич только `auth`, `news` и `notifications`: Rollup кладёт в файл ядра всё, что импортируют его модули, не глядя на tree-shaking, поэтому в этих трёх фичах нет ничего, кроме кода ядра. Импорт `index.ts` другой фичи из `app/Layout.tsx` или из них утянет в ядро всю фичу.
- Экран для ученика или родителя кладём в фичу домена: уведомления ученика — `inbox`, кабинет родителя — `parents`.

### Общий пакет: `packages/shared`

Здесь то, что должно совпадать на клиенте и сервере: каталог героя, уровни, значки и типы ответов API в `packages/shared/src/api/<домен>.ts` (импорт `@heroes/shared/api`). Сервисы объявляют эти типы в возвращаемых значениях, поэтому расхождение видно компилятору; даты из базы превращаются в строки ISO на стороне сервиса. В пакете нет кода браузера, Node.js и базы данных.

### База данных

- Миграции только вперёд, новая создаётся через `sh scripts/new-migration.sh <имя>`.
- Изменение существующих данных — в той же миграции. Сохранённых героев нельзя сбрасывать на значения по умолчанию.
- `prisma migrate reset` не используем: тесты работают во временной схеме.

## Лимиты размера

Новый код укладывается в лимиты. Файл сверх лимита нельзя увеличивать: сначала вынеси часть.

| Что | Лимит |
|---|---|
| Файл маршрутов модуля | 200 строк |
| Файл сервиса | 250 строк |
| Страница | 150 строк |
| Компонент | 300 строк |
| Длина строки | 140 символов, кроме данных SVG |

Данные каталога героя лимитами не ограничены. Длинные строки с классами Tailwind в JSX, написанном до введения правил, переносятся при заметной правке этого кода.

## Перед коммитом

- Полная проверка: `sh scripts/ci.sh`. Типы, тесты фронтенда и API, сервис подсчёта и e2e на отдельном стенде.
- Новая функция идёт с тестами: API для правил и прав, фронтенд для поведения, e2e для основного сценария. Новые экраны входят в проверки доступности и ширины 375 px.
- Новая зависимость: только лицензия, допускающая закрытое коммерческое использование (MIT, Apache-2.0, BSD и подобные). Проверь и транзитивные зависимости, запиши в DECISIONS.
- Закончил пункт — обнови ROADMAP. Принял неочевидное решение — запиши его в DECISIONS.
- Один коммит — одна задача. Не добавляй в него чужие незакоммиченные правки.
